## 2. 关键阻塞：工具链被迫替换（Foundry → Hardhat）

### 2.1 环境探测结果

| 目标 | 结果 | 影响 |
| --- | --- | --- |
| `github.com` / `api.github.com` / `raw.githubusercontent.com` / `objects.githubusercontent.com` | **全部超时不可达（000）** | **决定性**：Foundry 分发包托管于 GitHub Releases；`forge install` 依赖 GitHub 克隆 |
| `binaries.soliditylang.org` | ✅ 200 | solc 编译器官方可下载 |
| `registry.npmjs.org` | ✅ 200（ping 1003 ms） | npm 生态可用 |
| `registry.npmmirror.com` | ✅ 200 | 备用镜像可用 |
| `pypi.org` / `mirrors.aliyun.com/pypi` | ✅ 200 | **Slither 可安装**（静态分析门禁可恢复） |
| `forge` / `cast` / `anvil` / `solc` / `pnpm` | ❌ 均未安装 | 原方案工具链不可用 |

### 2.2 决策

**Foundry 无法安装 → 采用 Hardhat 2.x 作为等价替代。**

理由：Hardhat 完全经由 npm 分发（源可达），其 solc 编译器从 `binaries.soliditylang.org` 下载（可达），且 `@openzeppelin/contracts`、`@semaphore-protocol/contracts` 均可在 npm 获取。三者构成完整可运行的 EVM 开发闭环，无一处依赖 GitHub。

### 2.3 影响面与等价映射

| 原方案（Foundry） | 替代方案（Hardhat） | 等价性 |
| --- | --- | --- |
| `forge build` | `hardhat compile` | ✅ 等价 |
| `forge test` | `hardhat test`（mocha + chai） | ✅ 等价 |
| `anvil` | `hardhat node` | ✅ 等价（RPC 兼容） |
| `cast` | `hardhat console` / `ethers` 脚本 | ✅ 等价 |
| `forge script` + `--verify` | Hardhat Ignition / 自研 `script/*.ts` + `hardhat-verify` | ✅ 等价 |
| `forge coverage` | `solidity-coverage`（随 toolbox） | ✅ 等价 |
| `forge snapshot` | `hardhat-gas-reporter`（`REPORT_GAS=true`） | ✅ 等价 |
| `forge fmt` | ❌ 无直接等价 | ⚠️ **缺口**：需引入 `prettier-plugin-solidity`（P1 处理） |
| `forge install` | `npm install` | ✅ 等价 |
| `forge invariant` | ❌ **无成熟等价** | ⚠️ **缺口**：INV-1 ~ INV-9 的断言方式需重新选型（见 §7） |
| Slither / Echidna / Medusa | Slither 可经 PyPI 安装；Echidna/Medusa 为 GitHub 分发 | ⚠️ **部分缺口** |

### 2.4 必须知晓的后果

1. **v2.1 §10 的 P0–P14 DoD 中所有 `forge *` 字样的验证动作需按上表替换**，已记入 §8 的文档修订要求。
2. **不变量测试（INV-1 ~ INV-9）的实现路径需在 P6 前重新决策**：Foundry 的 `invariant` 无成熟替代。候选：（a）采用 `hardhat` + 状态机随机测试自研；（b）在具备 GitHub 访问的 CI 机器上保留 Foundry 专门跑 invariant；（c）改用 Echidna/Medusa（需 GitHub 访问）。
3. 本次为**环境适配决策，不改变任何业务设计**。C1–C4 冲突修正、Q1–Q12 冻结结论、21 项评审修订全部不受影响。

## 5. 过程中发现并修复的 3 个问题

### 问题 1 · TypeScript 7 与 ts-node 10 不兼容（已修）

| 项 | 内容 |
| --- | --- |
| 现象 | `npx hardhat compile` 报 `TypeError: Cannot read properties of undefined (reading 'fileExists')`，栈顶指向 `ts-node/src/configuration.ts:161` |
| 根因 | npm 自动解析出 **TypeScript 7.0.2**。TS 7 移除了 ts-node 10.9.2 依赖的 `ts.sys` 接口，导致 ts-node 读取 tsconfig 时崩溃。这是版本组合问题，与合约代码无关 |
| 定位手法 | `node -p "require('./node_modules/typescript/package.json').version"` → 7.0.2；`typeof require('typescript').sys` → `undefined`（应为 `object`） |
| 修复 | `npm install -D typescript@5.6.3`，锁定 TS 5.x；复核 `ts.sys === object` 后编译通过 |
| **教训** | `hardhat-toolbox@5` 未对 `typescript` 设上限约束，安装会随机拉到 TS 7。**必须显式锁定 `typescript@5.x`**，否则任何新环境都会复现 |

### 问题 2 · ethers v6 的 view 返回值是只读代理，不可作为实参回传（已修）

| 项 | 内容 |
| --- | --- |
| 现象 | 测试 `encode(decode(mask)) === mask` 报 `TypeError: Cannot assign to read only property '0' of object '[object Array]'`，栈指向 ethers 的 ABI `fragments.ts` |
| 根因 | ethers v6 的 `Result` 是冻结的 Proxy 数组；再次作为数组实参传入合约调用时，ethers 的参数解析会尝试写入其索引而失败 |
| 修复 | 传回前显式转换：`Array.from(await h.decode(...)).map(Boolean)` |
| **教训** | 任何"合约 A 的返回值直接喂给合约 B"的链式调用（P3/P10 的前端与索引器代码会大量出现）都必须先做浅拷贝，否则在运行时才炸 |

### 问题 3 · `BallotCodec.validate` 的职责边界需显式定义（文档化）

| 项 | 内容 |
| --- | --- |
| 现象 | 测试断言 `validate(mask=1, optionCount=1, maxChoices=1) === false` 失败，实际返回 `true` |
| 结论 | **非合约缺陷，而是职责划分问题**：`BallotCodec` 只判定"位图是否合法"，"至少 2 个选项"属业务规则，由 `Params.validateOptions` 承担 |
| 处置 | 保留职责分离设计（codec 纯位图语义，业务下限归 Params），并修正测试期望、补充注释说明 |
| 理由 | 若把业务下限塞进位图库，`BallotCodec` 将无法被复用于其他位宽场景，且两个校验点的重复检查会掩盖真实错误来源 |

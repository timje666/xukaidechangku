## 3. 关键技术结论（已坐实）

- **ZK 信号布局一致**：`generateProof` 与 `SemaphoreVerifier` 公开信号同为 `[root, nullifier, keccak256>>8(message), keccak256>>8(scope)]`（见 spike 文档）。
- **Merkle 根兼容（spike 未覆盖、P9 已确认）**：`@semaphore-protocol/group@4.14.3` 内部为 `@zk-kit/lean-imt@2.2.5`，与链上 `VoterRegistry` 的 LeanIMT **同构**（同一 Poseidon 参数）。前端按 `VoterRegistered.leafIndex` 升序重建成员即可复现冻结根，`castVote` 不会 `RootMismatch`。
- **`ballotCommitment` 一致**：`Poseidon4([mask,salt,SCOPE])` 用 `poseidon-lite`（group 同库），与 `poseidon-solidity PoseidonT4` 逐字一致。

## 4. 已知限制（沙箱约束，用户/CI 验收）

- **真实 ZK 快乐路径**：snark 产物在沙箱出口被拦（403），故 `generateProof` 真实路径需在可达 egress 的环境（`fetch:snark` + `NEXT_PUBLIC_USE_MOCK_PROOF=false`）验收；沙箱走 `USE_MOCK_PROOF` 驱动 UI/中继/合约错误分支。
- **本地端到端**：需 `npx hardhat node` + 部署 + `apps/relayer` 起服务；`RUN_E2E=1 npm test` 覆盖 scopeOf 与名册重建的链上一致性。

## 5. 本地运行

```bash
# 1) 合约链（另开终端）
cd contracts && npx hardhat node &            # :31337
npx hardhat run script/deploy.ts --network localhost   # 写入 deployments/hardhat.json

# 2) 前端
cd apps/web && cp .env.example .env && npm run dev      # :3000

# 3) 中继（另开终端）
cd apps/relayer && cp .env.example .env && npm start    # :4100

# 4) 单元/集成测试
cd apps/web && npm test
```

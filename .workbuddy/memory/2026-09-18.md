### 已冻结决策

N1 身份准入｜N2 地址白名单｜N3 链上时间锁（管理员不可提前结束/延时）｜N4 分步公示（投票期不可见票数）｜N5 多提案并行（独立白名单+独立时间锁）｜N6 结果签名核验｜N7 原有架构不变

### ★ 本轮最有价值的产出：4 处设计冲突修正（文档 §2，勿遗忘）
- **C1 白名单 vs 全匿名**：破坏匿名的是**投票交易的 sender**，不是白名单本身。
  → 两段式准入：登记期录 `whitelist[addr]=commitment`；投票期 ZK 证明 + **交易由 Relayer 代发**。**Relayer 是全匿名的必要条件，不是优化项。**
- **C2 链上锁票**：公开链 storage 可直读，UI 隐藏≠隐私。
  → 必须「承诺—揭示」两层：投票期只存 `Poseidon(mask,salt)`；揭示期验哈希后累计。
  关键论证：N4 的防护目标是防跟风，该风险**只在投票期成立**，揭示期渐进公开无风险 → 自洽。
- **C3 合约签名**：EVM 合约无私钥，**无法签名**。等价物＝`resultHash` 锚定 + 独立复算（view 接口 + 脚本），成本极低。L2（观察员 EIP-712 签名）信任模型不同，不推荐。
- **C4 暂停权冲突**：v1 的 `PAUSER_ROLE` 与 N3 直接冲突 → **完全移除暂停接口**，阶段仅由 `block.timestamp` 推导。

### 架构关键点
- 合约：`ProposalFactory` + **一提案一 `Proposal` 实例** + `VoterRegistry` + `SemaphoreVerifier` + `MinimalForwarder`(ERC-2771)。命名由 Election 改为 Proposal。
- 四阶段状态机：`REGISTRATION → VOTING → REVEAL → FINALIZED`（+`revealEnd`），参数全部不可变。
- 多选：`uint16` 位图。**隐选项的代价**——投票期看不到位图，`maxChoices` 只能在揭示期校验，违规票作废（计入 `revealedUnused` 并公示）。
- 信任模型：唯一需信任管理员的是「名册准确性」，且全程上链留痕。
- 不变量 INV-1~INV-7（新增：阶段单调、名册冻结）。
- 风险新增 R13 Relayer 审查 / R14 揭示期弃权 / R16 登记权滥用。
- 单票合计 gas 约 300k–420k（投票 250–350k + 揭示 50–80k）。
- 实施 P1~P14；相对 v1 工期约 +25%~+35%。

### 待用户答复的阻断项（Q1/Q2/Q4/Q6/Q9）
Q1 是否引入 Relayer｜Q2 是否接受揭示期渐进公开｜Q4 是否放弃暂停权｜Q6 `maxChoices` 上限｜Q9 未揭示票处理。
非阻断：Q3 揭示窗口(推荐48h) / Q5 Relayer 额度 / Q7 生物核身二期 / Q8 揭示 gas 补贴 / Q10 观察员签名 / Q11 主网选 Base / Q12 揭示由谁广播。

### ★ 评审最重要的发现：F-02（严重，凭空造票）
原 `reveal()` 校验链只有「哈希匹配 + 未揭示 + popcount 合规」三项，**全部可由攻击者自造数据满足**：
攻击者任选 `mask/salt` → 自算 `Poseidon(mask,salt)` → 直接揭示 → **无限造票**，名册准入与 ZK 凭证全部失效。
**修复**：投票期写 `_commitmentCast[commitment]=true`，揭示期首行校验 `CommitmentNotCast()`。→ 新增 INV-8 + R17。
**通用教训（已写入报告 §5）**：设计文档通过评审 ≠ 实现安全。必须专项复核三类路径：
① 每个 mapping 写入是否有前置存在性/合法性校验；② calldata 输入是否都经链上验证；③ 批量循环中单条失败是否影响整批/可否反复触发。

### 其余 20 项（高 5 / 中 8 / 低 7）
- F-01 `phase()` 空档期返回 REGISTRATION → 名册锁定后仍可登记，破 INV-7。修：加 `IDLE`/`CLOSED` + **registerVoters 禁用 phase()**。
- F-03/F-04 `castVote` 参数冗余且 `uint256[8]` 类型不成立 → 改为单一 `ZKProof{merkleTreeRoot,nullifier,message,scope,points[8]}`，nullifier/message 只从 proof 读。
- F-05 `_nullifierUsed` 写入时点未约束 → 可在 verifyProof 前写脏状态 DoS 合法选民。修：G8 明确顺序 + INV-9。
- F-06 缺 `frozenRoot` 固化触发函数 → 新增无权限 `freezeVotersRoot()`（幂等）。
- F-07 INV-1 无计数器 → 加 `totalMarks`。
- F-08 揭示失败票无法标记可无限重试 → `RevealStatus{NONE,ACCEPTED,REJECTED}`。
- F-09 登记 gas 低估 3–4 倍（实为 60–100k/地址）→ 单批 ≤ 50 地址（原写 200）。
- F-10 EIP-712 必须绑定 `to` + `keccak256(data)` + `deadline`，否则跨 calldata/跨提案重放。
- F-11 匿名性质是「不可链接到真实身份」（假名性），**不得对外称「完全匿名」**——链上 `nullifier ↔ 选项` 关联可见。
- F-13 Q8 补贴若经 Relayer 代发 reveal 会泄露明文 → 改事后报销（与 Q12 一致）。
- F-17 揭示率 95% 是**监控指标非可回退项**（延长窗口与 N3 冲突）→ AS-17。
- F-21 `BallotCodec.validate` 的 `optionCount >= 16` off-by-one。

### ★★ 最重大发现：本机 GitHub 不可达 → Foundry 工具链整体不可用
- 探测：`github.com` / `api.github.com` / `raw.githubusercontent.com` / `objects.githubusercontent.com` **全部超时**；

  **GitHub 被墙的环境里 Foundry 无法安装**。Echidna / Medusa 同理。
  但 **solc 编译器（官方 CDN）与 npm 生态可达 → Hardhat 完全可用**。

### ★ 实测踩坑（三个，均可复用）
1. **TS 7 与 ts-node 10 不兼容** → `hardhat compile` 崩在 `Cannot read properties of undefined (reading 'fileExists')`。
   根因：`hardhat-toolbox@5` 未限制 typescript 上限，npm 拉到 **7.0.2**，TS 7 移除了 ts-node 依赖的 `ts.sys`。
   **修复：显式 `npm i -D typescript@5.6.3`**。已定为【硬约束 5】——否则任何新环境都会复现。
2. **ethers v6 的 view 返回值是只读 Proxy** → 直接作为数组实参回传报
   `Cannot assign to read only property '0' of object '[object Array]'`。
   修复：`Array.from(await h.decode(...)).map(Boolean)`。链式调用（P3/P10 前端与索引器）必踩。
3. **Git Bash 下 `taskkill //F //PID` 参数被路径转换破坏** → 报「无效参数/选项 - '//F'」。
   改用 PowerShell 按端口杀：`Get-NetTCPConnection -LocalPort <P> -State Listen | Stop-Process -Force`。
